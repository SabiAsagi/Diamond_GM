# 2.1.1 입학식과 야구부 첫 미팅

새 커리어는 다음 순서로 시작한다.

1. 입학식 후 교실에서 담임, 반장, 짝꿍을 소개받고 반 친구들의 자기소개를 듣는다.
2. 야구부 단체 미팅에서 감독, 기술 코치, 주장, 입학 동기를 만난다.
3. 기존 다섯 질문의 개인 면담으로 가족 배경과 플레이 성향을 결정한다.
4. 첫날 저녁부터 자유 활동을 시작한다. 입학식과 미팅을 다시 소비하지 않는다.

각 소개 장면 완료 시 해당 인물만 인연 목록에 등록된다. 대사마다 화자 이름과 초상화를 바꾸고 소개 장면 안에서 이름을 보여준다. 소개 전에는 일반 인연 목록과 활동에서 이름을 공개하지 않는다. 교실·팀 소개의 완료 단계와 다음 장면을 함께 저장하여 재접속 후 입학식부터 반복하지 않는다. 저장 실패 시 등록과 다음 단계 전환을 모두 미룬다.

반장(classLeader)은 학생 캐스트의 여덟 번째 역할이다. 새 회차에서는 이름·성별·교복 및 사복 초상화를 함께 정한다. 기존 친구 이미지 풀에서 사용하지 않은 프로필을 선택하므로 같은 회차의 동네 친구와 얼굴이 겹치지 않는다. 기존 저장에 반장 캐스트가 없으면 기본 인물을 사용하며 기존 일곱 인물은 바꾸지 않는다. 반장과 수업 자료 정리(학업 +2·반장 인연 +4), 개별 대화(반장 인연 +6)가 가능하다. 로맨스 대상이나 경기 능력 보정은 추가하지 않았다.

2.1.0 저장의 진행과 기존 인연은 유지한다. 반장을 만나지 않은 저장은 기존 개별 첫 만남 방식으로 소개한다. 점진적 인연 도입 이전의 저장은 기존 인물 보존 정책을 유지한다.

자동 검사 101개가 통과했다. 기존 1학년 완주 8종과 3개년 연결을 유지하며, 교실/야구부 소개 순서·저장 실패·재접속·중복 등록 방지·반장 활동·여덟 캐스트 이름 및 초상화 중복을 검사했다. 정적 검사와 배포 빌드도 성공했다.

브라우저에서 새 선수 생성 → 담임/반장/짝꿍 소개 → 팀 미팅 도중 새로고침 → 감독 개인 면담 완료 → 첫날 저녁과 인연 카드까지 확인했다. 실제 사용자의 기존 저장과 전체 3년 수동 플레이는 이번 확인 범위에 포함하지 않았다.
