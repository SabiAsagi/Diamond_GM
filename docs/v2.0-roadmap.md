## 1학년 완주 자동 검증 (1.10 도입, 1.11 전국체전·1.12 겨울훈련 추가)

실행: `npm run test:freshman`. 전체 회귀: `npm test`. PR 검증 워크플로와 main 배포 워크플로 모두 전체 테스트를 실행한다. 워크플로 추가만으로 GitHub의 필수 검사/브랜치 보호 설정을 변경하지는 않는다.

`freshman_year.cjs`는 실제 TypeScript 소스를 임시 CommonJS로 컴파일하고 게임 스토어를 실행한다. 실제 `selectActivity`·`executeForcedSlot`·`resolveCutscene`·`revealTournament`·`dismissRivalReport`를 사용한다. 날짜를 직접 수정하거나 경기 승패를 강제하지 않는다. 활동은 시간대·등교일·포지션 조건을 만족하는 후보에서 선택하며 피로가 쌓이면 휴식한다.

타자/S학교(seed 19), 투수/D학교(seed 110), 투타겸업/B학교(seed 2026)를 각각 실행한다. 고정 시드는 실패 재현을 위한 것이며 승패를 고정값으로 대체하지 않는다. 실행 종료 후 난수 함수는 복원한다. 각 시나리오는 별도의 초기 선수로 시작하며 게임은 2026년 3월 2일 오전부터 2027년 3월 1일 오전까지 364일·1,092슬롯을 진행한다.

검사 항목:

- 날짜·요일·슬롯 연속성과 2학년 진급, 조기 커리어 종료 없음
- 기존 전국대회 4종, 주말리그, 청백전·연습경기 진행 및 저장된 결과
- 11월 1일 기준 시·도 대표 선발전과 전국체전 15경기가 결승까지 끝났는지, 선발전 우승 시에만 전국체전에 출전했는지(1.11)
- 경기일을 넘긴 미진행 경기와 중복 경기 없음
- 여름·겨울 방학 오전 자유 활동, 겨울방학에만 겨울 전용 활동을 선택하고 실제로 실행되는지(1.12)
- 컷신, 조 추첨, 월간 보고서 처리와 정체 방지
- 47슬롯마다 및 월 경계에서 저장본 재접속: 시계·대회·개인 기록·경쟁 상태·대기 이벤트 유지
- 능력치 유효 범위, 동기 진급, 연간 경기 기록 보존
- 실패 시 시드·진행 슬롯 수·최근 8개 행동 출력

1.10 초기 실행에서 세 시나리오 모두 35회 재접속, 12회 월간 보고서, 4회 조 추첨을 거쳤다. 1.11부터 제주 학교 시나리오(seed 107)를 더해 4개 시나리오를 실행한다. 선발전이 있는 3개 시나리오는 선발전에서 탈락해 다른 학교가 대표로 나갔고, 제주 시나리오는 선발전 없이 대표로 전국체전 경기를 치렀다.

## 1.11 전국체전

- **시·도 대표 선발전 (6월)**: 내 시·도 학교 전체가 6/9·6/11·6/16·6/18·6/23 평일에 단판 토너먼트를 치른다. 라운드 수가 적으면 뒤쪽 날짜만 쓴다. 참가 학교가 2의 거듭제곱이 아니면 1회전 부전승이 생긴다. 학교가 1개뿐인 시·도는 선발전 없이 대표.
- **전국체전 (10월)**: 16개 시·도 대표 단판 토너먼트. 실제 대회의 틀만 참고한 게임 일정(1회전 10/16~10/18 하루 최대 3경기, 8강 10/18~10/19, 휴식 10/20, 4강 10/21, 결승 10/22)을 매년 쓰고, 1회전 시·도 배치는 매년 무작위로 정한다. 다른 시·도 대표는 지역 최상위 등급 학교 중 1개교.
- **진행**: 선발전은 기존 라운드 방식(다음 라운드 날짜만 선발전 일정 사용). 전국체전은 경기마다 날짜가 달라 대진표 트리(다음 라운드 k번째 = 이전 라운드 2k·2k+1번째 승자)로 편성한다. 선발전 결승이 끝나면 우승교가 전국체전의 시·도 자리를 채운다.
- **이전 저장본**: 선발전 첫날 전이면 선발전부터, 이후면 내 학교가 대표로, 전국체전 개막 이후면 추가하지 않는다.
- 1.10의 TODO는 일반 검사로 전환했다. 현재 **51개 통과, TODO 0개**.

## 1.12 겨울훈련

- **기간**: 기존 겨울방학 구조(12/24~2/5, `isWinterVacation`)를 그대로 쓴다. 활동에 `season: 'winter'`를 붙이면 이 기간에만 선택지에 나오고, 스토어도 기간 밖 선택을 거부한다. 날짜를 모르면 열지 않는다.
- **활동 8개**(기존 카테고리에 추가): 훈련 5(동계 서킷, 겨울 벌크업 웨이트, 언덕 러닝, 실내 불펜 폼 다지기[투수], 실내 케이지 티배팅[타자]), 휴식 1(아버지와 찜질방), 인연 1(동계 합숙 야식), 특별 1(비시즌 목표 설정 면담). 시간대·포지션 제한은 기존 규칙을 따른다.
- **효과**: 겨울 훈련은 기존 훈련(능력치 합 +3, 체력 -12 안팎)보다 효과가 조금 크고(+4) 피로도 크다(체력 -14~-16). 인연 보상은 `relationshipTargets`로 지정한다.
- 겨울방학 오후 기본 일정 이름을 "동계 훈련 기간 · 팀 훈련"으로 표시한다.
- 검사: 날짜별 노출(12/23·2/6·여름방학 제외, 12/24·1/15·2/5 포함), 시간대·포지션 제한, 스토어에서 방학 중 효과(능력치·인연·피로)와 방학 전 거부, 1학년 완주 중 겨울 활동 선택·실행(시나리오별 6~8회). 현재 **53개 통과, TODO 0개**.

## 2.0 개발 완료와 최종 확인

1.13 학년 리포트, 1.14 월간 목표, 1.15 저장 안정화, 1.16 시즌 흐름·이어서 하기를 구현했다. 74개 자동 검사에 8개 1학년 완주와 3개년 연결을 포함한다. 기존 4개 시나리오에 투수/S학교(초기 능력 85), 포수/A학교, 중견수/C학교, 투타겸업/울산 시나리오를 추가했다. 3개년 연결은 날짜를 건너뛰지 않고 윤년을 포함한 3,285슬롯과 월간 평가 36개·학년 리포트 3개·졸업 후 재접속을 검사한다.

사용자가 “2.0 버전까지 쭉 달려줘 최종 확인은 나중에 해볼께”라고 지시했으므로 2.0 개발·병합을 진행하고 실제 UI 최종 확인을 후속 작업으로 남긴다. [최종 확인 목록](v2.0-release-checklist.md)에 범위와 경로를 정리했다. 전체 실제 플레이를 이미 검증했다고 표시하지 않는다.

저장은 구조화 복사한 메모리 객체를 사용하므로 실제 IndexedDB 영속성·브라우저 클릭·모달 배치·렌더링·사용자가 느끼는 지루함은 검증하지 않는다. 입학 면담을 마친 대시보드 상태에서 시작하므로 생성/입학 UI도 범위 밖이다. 이것은 **스토어 통합 완주 테스트**이고 브라우저 E2E 검사를 대체하지 않는다.
